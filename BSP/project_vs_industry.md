# 현재 프로젝트 수준 vs 현업 기준 비교

> **대상:** 모터 · 엔코더 · PID 제어 시스템 (`BSP/feat/motor-pid`)
> **작성일:** 2026-03-02

---

## 1. 아키텍처 & 제어 루프 타이밍

### 현재 프로젝트
PID 루프가 `while(1)` 안에서 `HAL_GetTick()` 비교로 실행된다.
`Protocol_Process()`나 `printf()`가 예상보다 오래 걸리면 10ms 주기가 밀린다 — 제어 루프가 진정한 의미의 주기적 실행을 보장받지 못한다.

### 현업 기준
하드 리얼타임 제어 루프는 **타이머 인터럽트(ISR)** 또는 **RTOS(FreeRTOS / Zephyr)** 의 고우선순위 태스크 안에서 동작한다. 제어 주기는 소프트웨어 폴링이 아닌 하드웨어가 보장한다.

---

## 2. PID 구현

### 현재 프로젝트
P 제어만 사용 (`Kp=1.0, Ki=0, Kd=0`). Anti-Windup 없음, 미분 필터 없음, 피드포워드 없음.
Ki=0 상태에서는 정상 상태 오차와 헌팅(hunting, 목표 속도 주변 진동)이 구조적으로 발생한다.

### 현업 기준
최소 **튜닝된 PI 또는 PID + Anti-Windup** 적용.
정밀 로봇 제어에서는 **캐스케이드 제어(cascade control)** 가 일반적이다:

```
외부 루프 (속도 PI) → 내부 루프 (전류 P)
```

더 발전된 구조는 **피드포워드 + 피드백** 조합이다.
피드포워드가 모터 모델로 필요한 PWM을 예측하고, PID는 잔차 오차만 보정한다.

---

## 3. 엔코더 & 속도 추정

### 현재 프로젝트
Raw `delta / dt` 방식. 구현이 단순하지만 **저속 구간에서 노이즈가 크다.**
엔코더 1 tick의 오차가 그대로 속도 스파이크로 나타난다.

### 현업 기준
속도 추정값에 **이동평균(Moving Average)** 또는 **저역통과필터(LPF)** 를 적용한다.
정밀도가 필요한 시스템은 **속도 관측기(Velocity Observer)** — Luenberger 관측기 또는 칼만 필터 — 를 사용하여 엔코더 데이터와 모터 모델을 융합, 지연 없이 부드러운 속도 신호를 얻는다.

---

## 4. 안전 & 결함 처리

### 현재 프로젝트
안전장치가 하나뿐이다 — **500ms 명령 타임아웃 → SoftStop**.
엔코더 고장, 모터 스톨, 과전류, H-브리지 결함 감지는 없다.

### 현업 기준
계층적 안전 구조(Layered Safety Architecture):

| 계층 | 메커니즘 |
|------|---------|
| MCU 하드웨어 | 독립 와치독 타이머 (IWDG) |
| 모터 라인 | 전류 감지 → 과전류 차단 |
| 소프트웨어 | 엔코더 신뢰성 검증 (명령 속도 vs. 실측 속도 차이 감시) |
| 시스템 | 결함 상태 머신 (Normal → Fault → Safe State → Recovery) |

---

## 5. UART 통신

### 현재 프로젝트
바이트당 인터럽트 방식 수신, 단일 `packet_ready` 플래그(링 버퍼 없음).
MCU가 다른 처리로 바쁠 때 다음 패킷이 수신되면 **패킷 드롭** 이 발생한다.
체크섬은 XOR 방식 (신뢰도 낮음).

### 현업 기준
- **DMA 기반 수신 + 원형(Ring) 버퍼**: CPU 개입 없이 데이터 수신, 드롭 방지
- **CRC-16 또는 CRC-32** 체크섬: XOR 대비 오류 검출률 수십 배 향상
- **ACK/NACK + 재전송 프로토콜**: 패킷 손실을 상위 레이어에서 복구

---

## 6. 비교 요약표

| 항목 | 현재 프로젝트 | 현업 최소 기준 |
|------|-------------|--------------|
| 제어 루프 타이밍 | `while(1)` 폴링 | 타이머 ISR / RTOS 태스크 |
| PID | P 제어만, Anti-Windup 없음 | 튜닝된 PI + Anti-Windup |
| 속도 추정 | Raw delta/dt | LPF 또는 관측기 |
| 안전장치 | 500ms 타임아웃 1개 | IWDG + 결함 상태 머신 |
| UART 수신 | ISR per byte, XOR 체크섬 | DMA + 링 버퍼, CRC-16 |
| 모터 전류 감지 | 없음 (개방 루프 전압 제어) | 전류 피드백 (선택적) |

---

## 7. 결론

이 프로젝트는 **구조적으로 올바른 기반**을 갖추고 있다.
계층화된 아키텍처, 바이너리 통신 프로토콜, 하드웨어 타이머 엔코더 모드,
`drv_motor` / `algo_pid` / `drv_encoder` 의 모듈 분리는 모두 올바른 설계 방향이다.

부족한 부분들은 개념적 실수가 아니라, **프로토타입에서 실제 제품으로 넘어갈 때 누구나 거치는 다음 단계**들이다:

1. Ki 튜닝 + Anti-Windup 추가
2. 제어 루프를 타이머 ISR로 이전
3. UART에 DMA + 링 버퍼 적용
4. 결함 감지 및 상태 머신 추가
