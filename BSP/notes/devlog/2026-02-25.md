## [Review] 현재 코드로 하드웨어 테스트 가능 여부 점검

`main.c` + `motor_control.c` + `encoder.c` + `pid.c` 전체를 읽고 PID 제어 루프의 동작 흐름을 검토했다.

**결론: 기본 테스트 가능. 단 아래 3가지 전제 필요.**

| 항목 | 상태 | 비고 |
|---|---|---|
| 바퀴 지름 | ⚠️ 미실측 | `WHEEL_CIRCUMFERENCE_MM = 204.2f` (π×65mm 가정) — 실측 후 수정 필요 |
| PID 게인 | ⚠️ 미튜닝 | `Kp=1.0, Ki=0, Kd=0` 초기값 — 하드웨어에서 조정 필요 |
| 적분 와인드업 | ℹ️ 미구현 | Ki=0이라 당장 문제없음 — Ki 올리기 전에 추가 필요 |

PID 출력이 mm/s 단위로 해석되어 `Motor_SetRaw()`로 전달되는 구조가 특이하지만, `Kp=1.0` 기준으로 동작은 합리적이다 (300mm/s 오차 → PWM 약 50%). 안전장치(타임아웃, ESTOP)도 정상 동작한다.

**테스트 순서:**
1. 바퀴 지름 실측 → `WHEEL_CIRCUMFERENCE_MM` 수정
2. 플래시 후 USART2 부팅 메시지 확인
3. RPi에서 `CMD_VELOCITY` 전송 → `[DIAG]` 출력 `spd L/R` 확인
4. Kp 조정 → 수렴 확인 후 Ki 고려

## [Review] 로봇 전원 설계 — 보조배터리 동시 다중 전압 출력 한계 분석

로봇에 사용할 보조배터리(USB-A 22.2W, C타입 20W) 스펙을 `docs/hardware/battery_powerbank_spec.md`에 정리하면서, 단일 보조배터리로 5V(RPi)와 9V/12V(모터)를 동시에 공급하는 것이 구조적으로 불가능하다는 것을 확인했다.

**원인:** 보급형 보조배터리는 승압 회로(DC-DC Boost)가 1개. 한 포트에 5V 기기가 연결되면 보호 회로가 모든 포트를 5V로 하향 고정 → 모터로 가던 9V/12V가 5V로 떨어짐.

**해결 방안 (우선순위 순):**
1. 보조배터리 2개 분리 사용 — 5V용(RPi)과 9V/12V 트리거 케이블용(모터) 분리
2. 65W 이상 고출력 배터리 1개 + 강압 모듈(Buck Converter) — 12V → 모터, 5V로 강압 → RPi
3. 포트별 독립 회로가 분리된 고가형 배터리 구매
