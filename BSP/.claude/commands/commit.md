다음 단계에 따라 커밋을 준비해줘.

## 1. 변경 사항 파악
`git status`와 `git diff`를 실행해서 변경된 파일과 내용을 확인해.

## 2. 커밋 그룹 나누기
변경 사항을 기능/목적별로 논리적으로 묶어. 하나의 커밋에 너무 많은 변경이 섞이지 않도록 해.

## 3. 커밋 메시지 제안
아래 규칙에 따라 각 그룹의 커밋 메시지를 작성해:

**형식:** `:깃모지코드: [타입] 설명`

| 깃모지 | 코드 | 타입 |
|---|---|---|
| ✨ | `:sparkles:` | [Feat] 새 기능 |
| 🐛 | `:bug:` | [Fix] 버그 수정 |
| 📝 | `:memo:` | [Docs] 문서 |
| 🗃️ | `:card_file_box:` | [Mod] 파일 수정 |
| 🎨 | `:art:` | [Style] 스타일 변경 |
| 🧪 | `:test_tube:` | [Test] 테스트 |
| ⚡ | `:zap:` | [Perf] 성능 개선 |
| 🙈 | `:see_no_evil:` | [Git] gitignore |

## 4. 사용자 확인 요청
제안한 커밋 내용(파일 목록 + 메시지)을 나에게 보여주고 확인을 받아.
확인이 되면 커밋을 실행해. **push는 하지 마.**

## 주의사항
- 커밋 메시지에 Claude 또는 AI 사용 관련 내용을 절대 포함하지 마.
- `Co-Authored-By` 같은 자동 서명도 추가하지 마.
- 언트랙 파일(untracked)도 필요하면 포함 여부를 물어봐.
